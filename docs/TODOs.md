### Feature 7：Embedding 模型变更后的 RAG 索引重建

> 状态：下一版本挂起，不纳入当前主 Feature 验收顺序。
> 背景：Kotaemon 提供基础索引管线和 `reindex=True` 单文件重建能力，但不负责 embedding 模型版本、向量维度变迁或新旧索引切换。

#### 目标与范围

- [ ] 记录每个 RAG Index 使用的 embedding 模型指纹（服务地址、模型名、可选 dimensions）及索引状态。
- [ ] 检测 RAG 模型配置变更，将受影响的 Index 标记为需要重建；模型名、服务地址或维度参数变化均视为变更。
- [ ] 复用 Kotaemon 的 Source 表、Index 表、文件存储和 `stream(..., reindex=True)` 管线，恢复来源文件并执行全量重建。
- [ ] 对 embedding 维度变化创建新的 Kotaemon FileIndex/向量 collection，不在旧 collection 中混写不同维度向量。
- [ ] 重建成功后原子切换节点的 collection 绑定及资料 source 映射，再异步清理旧 Index；重建失败时保留旧索引可用。
- [ ] 提供后台重建任务、进度、失败原因、取消和重试，并避免依赖浏览器请求持续连接。

#### 非目标

- 不修改 Kotaemon 底座的基础索引和向量存储实现。
- 不尝试对已有向量做维度填充、截断或数学转换；不同模型或不同维度必须重新生成 embedding。
